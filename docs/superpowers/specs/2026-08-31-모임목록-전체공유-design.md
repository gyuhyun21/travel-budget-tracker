# 모임 목록 전체 공유 설계

## 목적
지금은 모임(이벤트)을 하나씩 개별로 공유해야 한다. 사용자는 이걸 없애고, "모임 목록 전체"를 하나의 공유 단위로 만들어서, 링크를 가진 사람은 누구나 그 목록에 있는 모든 모임을 보고, 그 안에서 지출을 기록하고, 새 모임을 추가하고, 그 목록을 또 다른 사람에게 공유할 수 있게 하려고 한다.

## 현재 상태 (변경 전)
- 모임(이벤트)마다 독립적으로 `js/storage.js`의 `enableSharingForCurrentData()`/`disableSharing()`을 통해 Firestore로 개별 공유 on/off 가능.
- 공유된 모임은 Firestore `trips/{tripId}` 문서(설정) + `trips/{tripId}/expenses`, `trips/{tripId}/packingItems` 서브컬렉션으로 저장되고, `tripId`는 그 모임의 로컬 `id`와 항상 같음.
- `?trip=xxx` 링크를 열면 `initSharedModeFromUrl()`이 그 하나의 모임만 기기의 로컬 모임 목록(`cmb_events`)에 등록하고 바로 진입시킴.
- 모임 목록(`cmb_events`) 자체는 완전히 기기 로컬 전용이며 공유되지 않음.
- 설정 화면(개별 모임 안)에 "공유" 섹션이 있어 그 모임 하나만 켜고 끌 수 있음.
- 지금 실제로 개별 공유 중인 모임은 없음 — 마이그레이션 불필요.

## 데이터 모델 (변경 후)

### 기기 상태
- `cmb_shared_list_id` (localStorage, 신규): 이 기기가 지금 속해 있는 공유 목록의 id. 없으면 완전히 로컬 전용 상태.
- 기존 `cmb_events`, `cmb_active_event_id`, 이벤트별 `cmb_event_{id}_*` 키는 구조 변경 없음.

### Firestore
- 새 최상위 컬렉션 `lists/{listId}`: 문서 자체는 필드가 거의 없는 얇은 컨테이너(`createdAt`만 있으면 충분 — 목록 자체의 이름은 불필요, 각 모임 안에 이미 제목이 있음).
- 새 서브컬렉션 `lists/{listId}/events/{eventId}`: "이 목록에 어떤 모임이 속해 있는지"의 멤버십 기록. 문서 필드는 `addedAt`(추가된 시각)만 있으면 됨. eventId는 그 모임의 `trips/{tripId}`와 동일한 id를 가리킨다(모임 하나가 공유되면 `tripId === eventId`가 되는 기존 규칙을 그대로 따름).
- 기존 `trips/{tripId}` + 서브컬렉션(`expenses`, `packingItems`) 구조는 완전히 그대로 유지. 모임 하나를 열었을 때의 실시간 동기화(`subscribeToTrip`, `startSharedSync` 등)는 코드 변경이 필요 없다 — "목록에 속한 모임"도 결국 지금과 똑같은 방식의 개별 공유 모임일 뿐이다.

### 개별 공유 기능 제거
- 모임을 "개별로" 공유/공유중지하는 기능(설정 화면의 "공유" 섹션)은 완전히 삭제한다. 공유는 오직 "목록 전체 공유"로만 가능하다.
- `enableSharingForCurrentData()`/`disableSharing()`은 "활성 모임 하나"가 아니라 "목록에 속한 모임 하나"를 Firestore에 올리고 내리는 내부 헬퍼로 재정의되어, 목록 공유 로직에서 각 모임마다 호출된다(사용자가 직접 누르는 버튼은 더 이상 아님).

## 화면 구성

### 모임 목록 화면
- 헤더의 "+" 버튼 옆에 "공유" 아이콘 버튼을 추가한다.
- 누르면 시트가 열리고:
  - **공유 중이 아니면**: "이 모임 목록을 공유하면 링크를 가진 사람 누구나 모든 모임을 보고, 지출을 기록하고, 새 모임을 추가할 수 있어요." 안내 + "목록 공유하기" 버튼.
  - **공유 중이면**: 공유 링크(복사/공유 버튼 포함, 기존 개별 공유 UI의 링크 박스 재사용) + "공유 중지" 버튼.
- 공유를 시작하면 그 시점에 로컬에 있던 모든 모임이 자동으로 Firestore에 업로드되고 목록의 멤버십에 등록된다.

### 개별 모임의 설정 화면
- "공유" 섹션을 완전히 제거한다. "모임 상태"(마무리/재개), "위험 구역"(삭제)은 그대로 유지.

## 동작 흐름

### 목록 공유 시작
1. `generateShortId()`로 `listId` 생성.
2. `lists/{listId}` 문서 생성.
3. 로컬 `cmb_events`의 모든 모임을 순회: 아직 Firestore에 없는 모임(`tripId`가 없는 모임)은 그 모임의 로컬 데이터(설정/지출/준비물)를 `trips/{eventId}`로 업로드하고 `updateEventMeta(id, { tripId: id })`로 표시. 이미 있는 모임은 건너뜀.
4. 모든 모임의 id를 `lists/{listId}/events/{eventId}`에 등록.
5. `cmb_shared_list_id`에 `listId` 저장, URL에 `?list=listId` 반영.
6. `lists/{listId}/events`를 실시간 구독 시작 — 이후 새로 추가되는 모임(다른 멤버가 추가한 것 포함)을 감지해 로컬 `cmb_events`에 자동 등록한다.

### 공유 중 새 모임 생성
- `createEvent(title)` 호출 시, 기기가 지금 공유 목록에 속해 있다면(`cmb_shared_list_id`가 있다면): 로컬 생성 직후 그 모임도 즉시 `trips/{eventId}`로 업로드하고 `lists/{listId}/events`에 등록한다. 그러면 그 순간 다른 멤버들의 화면에도 실시간으로 나타난다.
- 공유 중이 아니면 지금처럼 완전히 로컬 전용 모임으로 남는다.

### 링크로 참가 (`?list=xxx`)
1. `lists/{listId}/events`를 구독.
2. 그 안의 각 `eventId`에 대해: 로컬 `cmb_events`에 없으면 새로 등록(그 모임의 `trips/{eventId}` 데이터를 그대로 이어서 실시간 동기화). 이미 있으면 그대로 둠.
3. 이 기기가 원래 갖고 있던 로컬 전용 모임(있다면)은 그대로 유지된다 — 참가는 "추가"이지 "교체"가 아니다.
4. `cmb_shared_list_id`를 저장하고 모임 목록 화면으로 이동(개별 모임 딥링크였던 `?trip=`과 달리, 목록 링크는 특정 모임이 아니라 목록 화면 자체로 진입한다).

### 공유 중지
- `lists/{listId}/events` 구독을 해제하고 `cmb_shared_list_id`를 지운다.
- 이 기기가 갖고 있던 모임 각각에 대해 기존 `disableSharing()`과 동일한 처리를 적용한다: 마지막으로 동기화된 데이터를 로컬에 스냅샷으로 저장하고, 그 모임의 `tripId`를 **반드시 null로 지운다**. tripId를 남겨두면 나중에 그 모임을 다시 열었을 때 `enterEvent()`가 "이 모임은 공유 중"으로 오판해 목록 밖에서 혼자 Firestore 구독을 재개해버리는 버그가 생기므로, "공유 중지 = 완전히 로컬 전용으로 전환"을 모든 모임에 대해 예외 없이 적용해야 한다.
- 다른 멤버들은 각자의 기기에서 계속 그 목록으로 실시간 협업을 이어간다 — 이 동작은 이 기기가 떠나는 것과 무관하다.

## 에러 처리 / 예외 상황
- 목록 공유 시작 도중 일부 모임 업로드가 실패하면(네트워크 오류 등) 전체를 롤백하지 않고 사용자에게 실패를 알리고 다시 시도하게 한다(기존 개별 공유 실패 처리와 동일한 수준).
- `?list=xxx`가 가리키는 목록이 Firestore에 없으면(삭제되었거나 오타) 오류 안내 후 모임 목록 화면으로 정상 진입시킨다.
- 목록에 속한 모임이 다른 멤버에 의해 삭제되면, 그 멤버십 문서(`lists/{listId}/events/{eventId}`)도 함께 삭제하여 다른 기기들의 목록에서도 사라지게 한다(모임 삭제 로직에 목록 멤버십 정리를 추가).

## Firestore 보안 규칙 (README 갱신)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trips/{tripId} {
      allow read, write: if true;
      match /expenses/{expenseId} {
        allow read, write: if true;
      }
      match /packingItems/{itemId} {
        allow read, write: if true;
      }
    }
    match /lists/{listId} {
      allow read, write: if true;
      match /events/{eventId} {
        allow read, write: if true;
      }
    }
  }
}
```

## 검증 계획
1. 새 목록을 공유 → 링크로 다른 기기(시크릿 창)에서 열었을 때 그 시점의 모임들이 모두 보이는지 확인
2. 공유 중인 상태에서 한쪽 기기가 새 모임을 만들면 다른 기기의 목록에도 실시간으로 나타나는지 확인
3. 공유 중인 목록의 한 모임에 들어가 지출을 추가하면 다른 멤버 화면에도 실시간 반영되는지 확인 (기존 개별 모임 동기화 재사용 확인)
4. 공유 중지 시 목록 구독이 끊기고, 이미 받은 모임 데이터는 로컬에 남아있는지 확인
5. 한 멤버가 모임을 삭제하면 다른 멤버의 목록에서도 사라지는지 확인
6. 개별 모임 설정 화면에서 "공유" 섹션이 완전히 사라졌는지 확인
7. Firestore 규칙에 `lists` 컬렉션이 추가되어 있는지 README와 실제 콘솔 설정 확인

## 범위 밖 (Out of Scope)
- 목록에 이름/제목을 붙이는 기능 (모임 각각에 이미 제목이 있으므로 불필요)
- 목록 안에서 특정 모임만 골라 공유를 끄는 기능 (개별 공유 개념 자체가 사라짐)
- 목록 멤버 목록 조회/추방 기능 (링크를 아는 사람은 모두 동등한 편집 권한을 가지는 기존 방식 그대로 유지)
- 기존에 개별 공유되던 데이터의 마이그레이션 (현재 실사용 데이터 없음, 확인 완료)
