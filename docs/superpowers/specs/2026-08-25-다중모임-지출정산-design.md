# 다중 모임(이벤트) 지원 + 예산 개념 제거 설계

## 목적
지금은 앱 전체가 "여행 하나"만 다룰 수 있는 구조라, 8월에 모임이 3번 있으면 매번 이전 모임을 지우고 새로 시작해야 한다. 이를 없애고, 여러 모임(여행/식사/행사 등)을 각각 독립된 기록으로 동시에 관리하다가, 정산이 끝난 모임은 "완료" 상태로 목록에 남겨 나중에 다시 찾아볼 수 있게 한다.

이 작업과 함께, "예산 대비 지출 관리" 성격이었던 앱을 "모임별 지출 기록 + N빵 정산" 도구로 명확히 전환한다 (예산 항목 완전 제거, 환율 입력 선택사항화).

## 현재 상태 (변경 전)
- `localStorage`에 `cmb_settings`(설정 1개) / `cmb_expenses`(배열) / `cmb_packing_items`(배열)가 각각 고정 키로 저장되는 단일 모임 구조.
- 설정에 총 예산, THB/USD 환율(둘 다 항상 입력칸 노출), 여행 기간(필수)이 있고, 대시보드는 예산 링 + 남음/초과 표시 중심.
- 실시간 공유는 기기 하나당 `cmb_shared_trip_id` 하나만 바인딩 가능 (지금 열려 있는 모임이 곧 그 기기가 공유 중인 모임).
- 하단 탭 4개: 대시보드 / 지출목록(+N빵) / 준비물 / 설정.

## 데이터 모델 (변경 후)

### Event 메타데이터 — `cmb_events` (localStorage, 배열)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 고유 식별자. 공유 중인 모임은 Firestore trip id와 동일한 값을 사용 |
| status | "active" \| "completed" | 진행중/완료 |
| tripId | string \| null | 공유 중(이었)이면 Firestore trip id, 로컬 전용이면 null |
| createdAt | number | 생성 시각 |
| updatedAt | number | 이 모임의 설정/지출/준비물이 마지막으로 바뀐 시각 (목록 정렬 기준) |

제목, 총 지출, 기간 같은 표시용 정보는 이 인덱스에 중복 저장하지 않고, 목록을 그릴 때마다 해당 모임의 Settings/Expenses를 읽어서 계산한다 (단일 소스, 동기화 버그 방지).

### Settings (모임별 1개, `cmb_event_{id}_settings`)
| 필드 | 타입 | 설명 |
|---|---|---|
| tripName | string | 모임 제목 |
| thbRate | number \| undefined | 1바트=?원. **모임 설정에서 추가했을 때만 존재** |
| usdRate | number \| undefined | 1달러=?원. **모임 설정에서 추가했을 때만 존재** |
| tripStartDate / tripEndDate | string \| undefined | 선택사항. 없으면 대시보드에 기간 배지 안 보임 |
| packingParticipants | {name, count}[] | 기존과 동일 (N빵 인원수 포함) |

`totalBudget` 필드는 완전히 제거한다.

### Expense / PackingItem
필드는 지금과 동일. 저장 위치만 모임별 키(`cmb_event_{id}_expenses`, `cmb_event_{id}_packing`)로 바뀐다.

### 활성 모임 포인터 — `cmb_active_event_id`
현재 화면에 열려 있는 모임의 id. `null`이면 모임 목록 화면을 보여준다.

## 화면 구성

### 0. 모임 목록 (신규 홈 화면)
- 앱을 새로 열면(브라우저 새로고침, PWA 재실행 포함) **항상 이 화면부터** 보여준다. 지난 세션에 어떤 모임을 보고 있었는지는 기억하지 않고 `cmb_active_event_id`는 카드를 탭하거나 공유 링크로 들어올 때만 채워진다. 유일한 예외는 `?trip=...` 공유 링크로 열었을 때 — 아래 "공유" 참고.
- 모임 카드 목록(최근 수정순): 제목 · 기간(있으면) · 총 지출 · 상태 배지("진행중"/"완료").
- 상단 필터 칩: 전체 / 진행중 / 완료.
- 우측 상단 "+"로 새 모임 생성: 제목 입력 사트만 받고(빈 값이면 막음) 바로 그 모임으로 진입.
- 카드를 탭하면 그 모임을 활성 모임으로 지정하고 대시보드로 진입 (이때부터 하단 탭바가 나타남).
- 모임이 하나도 없으면 "아직 모임이 없어요. + 로 새 모임을 만들어보세요" 빈 상태.

### 1. 대시보드 (변경)
- 헤더에 "← 모임" 링크 추가 → 누르면 모임 목록으로 돌아감 (활성 모임 해제).
- 예산 링/남음/초과 표시를 모두 제거.
- 히어로 카드(그라데이션)에 제목, 기간 배지(있으면), **"총 지출 000,000원"** 큰 숫자 하나만 표시.
- 카테고리별 지출, 최근 지출 목록은 지금과 동일하게 유지.
- 더 이상 "설정에서 예산/환율을 입력해주세요" 같은 진입 차단 빈 상태가 없다 — 모임을 만들면 곧바로 지출을 기록할 수 있다.

### 2. 지출 추가/수정 화면 (변경)
- 통화 선택 UI는 그 모임에 추가된 해외통화가 하나도 없으면 아예 표시하지 않고 원화로 바로 기록한다.
- 하나 이상 추가돼 있으면 지금처럼 세그먼트(원화 + 추가된 통화들)로 고를 수 있다.

### 3. 지출 목록 / N빵
변경 없음 (모임별로 독립된 지출 데이터를 보여줄 뿐).

### 4. 준비물
변경 없음.

### 5. 설정 (변경)
- "총 예산" 입력칸 삭제.
- "제목" 입력은 유지 (모임 이름 수정용).
- "여행 기간"은 선택사항으로 전환 — 비워둔 채 저장 가능.
- "환율" 섹션: 기본은 비어 있고, "해외통화 추가" 칩 목록(바트/달러 중 아직 안 추가한 것)에서 고르면 그 통화의 환율 입력칸이 나타남 (기본값 프리필, 수정 가능). 이미 추가된 통화는 x로 제거 가능 (제거 시 해당 `*Rate` 필드 삭제).
- 하단 "새 여행 준비"(초기화) 섹션을 다음 두 버튼으로 교체:
  - **모임 마무리** / **다시 진행중으로 변경**: `status`만 토글하는 순수 라벨 값이다. 지출 추가/수정, 준비물, N빵 등 다른 모든 기능은 완료 상태여도 전혀 제한 없이 그대로 동작한다 — "완료"는 목록에서의 분류 표시일 뿐, 잠금(lock)이 아니다.
  - **이 모임 삭제**: 이 모임의 설정/지출/준비물 데이터와 `cmb_events` 인덱스 항목을 모두 지우고 모임 목록으로 돌아감 (공유 중이었다면 이 기기만 로컬 연결 해제 — Firestore 원격 데이터는 지금의 "공유 중지"와 동일하게 남아있을 수 있음).
- "공유" 섹션은 지금과 동일하되 활성 모임 하나에만 적용된다.

## 저장 계층 (storage.js) 설계
- `getSettings/saveSettings/getExpenses/...` 등 기존 함수 이름과 시그니처는 그대로 두고, 내부적으로 `getActiveEventId()`가 가리키는 모임의 키로 읽고 쓰도록 바꾼다 (호출부인 `render.js`/`app.js`는 대부분 수정 불필요).
- 신규 함수: `getEvents()`, `createEvent(title)`, `updateEventMeta(id, fields)`(상태 토글 등), `deleteEvent(id)`, `getActiveEventId()`, `setActiveEventId(id|null)`.
- 지출/설정/준비물을 쓰는 모든 저장 함수는 그 모임의 `updatedAt`도 함께 갱신해 목록 정렬에 반영한다.
- 공유 모드(`isSharedMode()`)는 전역이 아니라 "활성 모임의 `tripId`가 있는가"로 판단하도록 바뀐다. 모임을 전환할 때 이전 모임의 Firestore 구독은 해제하고, 새로 연 모임이 공유 중이면 그 모임 기준으로 다시 구독한다.

## 공유(Firestore) 연동
- "이 모임 공유하기"는 활성 모임에 대해서만 Firestore trip을 만들고 그 모임의 `tripId`를 채운다. 지금처럼 `?trip=...` 링크가 생성된다.
- `?trip=xxx` 링크로 앱을 열었을 때: 이 기기의 `cmb_events`에 그 id가 없으면 새 항목(`status: 'active', tripId: xxx`)으로 등록하고, 바로 그 모임을 활성 모임으로 지정해 대시보드로 진입한다 (모임 목록 화면을 거치지 않음 — 지금의 딥링크 동작과 동일).
- "공유 중지"는 지금처럼 이 기기만 로컬 저장으로 되돌리되, `cmb_events`의 해당 항목은 유지되고 `tripId`만 비운다.

## 마이그레이션
자동 이전 없음 — 기존 백업 데이터가 없으므로 빈 모임 목록에서 시작한다. 예전 고정 키(`cmb_settings` 등)는 건드리지 않고 그냥 더 이상 읽지 않는다.

## 에러 처리 / 예외 상황
- 새 모임 제목이 빈 값이면 생성 막고 입력창에 포커스.
- 모임 삭제 시 확인 다이얼로그(`confirm`)로 되돌릴 수 없음을 안내 (기존 초기화 버튼과 동일한 패턴).
- 마지막 남은 모임을 삭제하면 목록 화면의 빈 상태로 돌아간다.
- 모임 전환 시 이전 모임의 Firestore 리스너를 반드시 해제해, 다른 모임 화면에 잘못된 실시간 데이터가 섞여 들어오는 일이 없게 한다.

## 검증 계획
1. 새 모임 생성 시 제목만 입력하면 바로 대시보드로 진입하고(예산/환율 입력 요구 없음), 지출을 바로 기록할 수 있는지 확인
2. 모임 A/B를 각각 만들어 지출·준비물을 넣고, 서로 데이터가 섞이지 않는지 확인
3. 모임 목록의 총 지출/상태 배지/필터 칩이 정확한지 확인
4. 모임 마무리 → 완료 배지로 목록에 표시 → 다시 열어서 지출 추가·수정 가능한지 확인
5. 모임 삭제 시 데이터와 목록 항목이 완전히 사라지는지 확인
6. 환율 추가/제거가 지출 추가 화면의 통화 선택 UI에 바로 반영되는지 확인
7. 공유 링크로 다른 기기(시크릿 창)에서 열었을 때 그 기기의 모임 목록에도 등록되고 바로 그 모임으로 진입되는지, 이후 모임 목록에서 다시 찾아볼 수 있는지 확인
8. 예산 관련 코드/문구가 전체 코드베이스에 남아있지 않은지 grep으로 확인
9. 모임을 전환할 때 이전 모임의 실시간 구독이 끊기고 새 모임 기준으로만 갱신되는지 확인 (공유 중인 모임이 있을 때)

## 범위 밖 (Out of Scope)
- 예산/한도 관리 기능 (이번에 완전히 제거하며, 재도입하지 않음)
- 모임 간 지출 이동/복사
- 모임 목록 정렬 옵션(최근 수정순 고정 외 다른 정렬 없음), 검색
- 기존 단일 모임 데이터 자동 이전
